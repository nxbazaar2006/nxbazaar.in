# Nxbazaar.in AI Architecture

## Goals

- Keep all provider calls server-side.
- Ground customer-facing answers in Nxbazaar.in database data only.
- Keep normal ecommerce flows working when AI is disabled or unavailable.
- Make the provider replaceable without changing feature routes.

## Core Modules

- `lib/ai/types.ts`: shared request/response/result types.
- `lib/ai/validators.ts`: Zod schemas for prompts, filters, feedback, generation requests, and support requests.
- `lib/ai/safety.ts`: prompt-injection checks, PII redaction, masking helpers, safe error messages.
- `lib/ai/rate-limit.ts`: AI-specific rate limit wrapper using Redis when available and in-memory fallback for local dev.
- `lib/ai/provider.ts`: provider-independent interface and OpenAI adapter selected by `AI_PROVIDER`.
- `lib/ai/prompts.ts`: immutable system prompts with database-only grounding rules.
- `lib/ai/audit-log.ts`: safe request/response logging into AI usage tables.
- `lib/ai/product-search.ts`: deterministic query parsing and Prisma/full-text product retrieval.
- `lib/ai/insights.ts`: database aggregation functions for admin/seller insights.

## Implemented Endpoints

- `POST /api/ai/product-search`: public semantic product search with safe deterministic filter extraction and product search logging.
- `POST /api/ai/shopping-assistant`: floating customer assistant grounded in returned product records only.
- `POST /api/ai/product-generate`: admin/seller/farmer product draft generation with editable preview and no product auto-save.
- `GET /api/ai/admin-insights`: admin-only database aggregation summary.
- `GET /api/ai/seller-assistant`: seller/farmer-only listing quality, low-stock, sales and review summary scoped to `session.user.id`.
- `POST /api/ai/feedback`: stores optional response feedback without requiring secrets or client-owned user IDs.

## Implemented UI

- Floating storefront AI assistant is mounted from the front-end layout when `AI_ENABLED` is not `false`.
- Product form includes `Generate with AI` draft preview and explicit Apply action.
- Reusable AI components live under `components/ai`.

## Request Flow

1. Route handler authenticates the user where required.
2. Route handler derives role/user/seller scope from server session.
3. Zod validates request body.
4. Rate limiter checks feature/user/IP key.
5. Safety layer rejects prompt-injection and redacts loggable text.
6. Feature code queries Prisma through allowlisted functions.
7. LLM receives only selected database facts, never raw unrestricted database access.
8. Response includes citations/product cards where applicable.
9. Audit log stores safe metadata, usage, latency, and status.

## Provider Contract

The provider should expose:

- `generateText(input)`
- `generateJson(input, schema)`
- optional `streamText(input)`

Provider output must be treated as untrusted until validated.

## AI Disabled Mode

When `AI_ENABLED=false`:

- Product search falls back to normal keyword/full-text search.
- Generate and assistant routes return deterministic database-grounded fallback responses where practical.
- No provider call is made.

## Data Grounding

Allowed AI data sources:

- Products, variants, inventory, category, subcategory, brand, HSN.
- Approved reviews only.
- Session-scoped customer orders.
- Session-scoped seller products/orders/sales.
- Admin-only aggregate metrics.

Disallowed:

- Raw SQL generated by the LLM.
- Client-provided `userId` or `sellerId`.
- Secrets, passwords, tokens, raw payment payloads.
